<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SSE event payload → DOM | tool name/input and result text originate from on-screen content and AppleScript output — must never be interpreted as HTML |
| screenshot base64 → <img src> | local data: URI rendered in the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering (DOM injection) | step-label / step-detail / error chip rendering | mitigate | Build all text with `textContent` and `createElement` only — `grep innerHTML == 0` is an acceptance gate. Tool input shown via JSON.stringify into a `<pre>.textContent`, never parsed as markup |
| T-02-04 | Information Disclosure | screenshot thumbnail + lightbox data: URI | accept | Image is rendered locally in Pietro's own browser from a 127.0.0.1 stream; single-user; no network egress. Same disposition as T-02-02 |
| T-02-05 | Denial of Service | malformed/huge base64 in screenshot event | mitigate | `if (ev.data)` guard skips empty payloads; img.loading="lazy"; a broken data URI degrades to a broken-image icon, never throws |
</threat_model>
