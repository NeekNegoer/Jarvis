<objective>
Fix the known Phase 1 carry-forward bug: screenshots Jarvis takes mid-turn never reach the
browser because `think_stream` listens for a top-level `tool_result` event that the claude CLI
NEVER emits. Per stream_debug_findings.md, tool results arrive inside `user` events whose
`message.content[]` holds `{"type":"tool_result","content":[...]}` blocks; an image is an inner
block. This plan makes `think_stream` emit `{"type":"screenshot","data":<b64>}` from those
events, parsed DEFENSIVELY (the exact image path is MEDIUM confidence — tolerate both the MCP
shape `{"type":"image","data":<b64>}` and the Anthropic shape `{"type":"image","source":{"data":<b64>}}`).

Purpose: UI-03 (inline screenshots) cannot work until the data actually flows. This is the
backend prerequisite for the activity panel.
Output: A corrected `think_stream` + a unit test proving screenshot events are yielded.
</objective>
